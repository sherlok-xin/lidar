# scfnr_ws 工程审查：看得见什么，哪些证据值得复用

**判断：它是一个单帧地面分割、障碍聚类和粉尘候选投影的传统基线。值得复用中间证据和显示接口，不宜直接使用最终删除规则或地图值代替实体真值。**

本记录依据 launch、实际 C++ 分支、地图写入和 RViz 配色。共享盘和本地 两套 src 下的 59 个常规文件逐一 SHA-256 相同（另有同目标 catkin 顶层符号链接）。本轮只读审查，没有回放 bag 或启动节点；下文红/白是配置含义，不是新测的预测结果。

## 对本项目意味着什么

1. **值得借鉴：相对地面的支持、是否有参考、形状残差有效性、逐阶段可视化。** 地面连接比例比直接用传感器 z 更适合分析起伏地面。将这些量作为独立证据层，与学习模型同帧比较，能看到误抑制发生在哪一步。
2. **不能把同角格远点认定为同束多回波。** 细障碍边缘和从旁边照到的远地面可落进同一角格；没有 return ID 来排除这个反例。代码还在标定平移后的坐标上取角，若原点不在光心，方向会偏。因此这只是一种观测线索，不足以自动删除近点。
3. **不能把不可用变成粉尘。** 有地面参考时，不成簇且高于0.5 m的点可直接判尘；悬浮簇拟合无效也可能整簇判尘。护栏横杆、行人上身、车辆遮挡边缘是应复核的反例，不是本次实测漏检。代码用约0.635°俯仰间隔估“线”，不是实读 ring；不应按此模型直接移植到80线。
4. **同格冲突会覆盖实体。** 同一格同时收到障碍和粉尘时，后写的13覆盖12。赋值结果是确定的，下游会如何解释并是否改变停车则未知。0只是未填，不是实测自由。选定聚类器没有返回非空 id 数组时，整个分类/地图发布段会跳过。
5. **点级评价不能用质心冒充原点。** ROI 内发体素质心，外部发原非地面点，没有 original_index。半径收集邻近点无显式去重，还可能包含簇外点。最近邻不能用来“精确恢复”原标签或给学习模型造真值。
6. **注释与执行有差异。** launch 的贴地比例是10%，README 的2%是源码缺省。PCL 的 nearestKSearch 返回平方距离：代码 gdist[0]<2 对应距离小于约1.41 m，不是注释中的2 m；dist[0]<0.3 是约0.55 m。点已换到车体系，发布时却复制输入 header；输入 frame_id 指雷达时可能标错坐标系。[PCL 接口说明](https://pointclouds.org/documentation/classpcl_1_1search_1_1_kd_tree.html)

## 最小后续对照（尚未实施）

在已审核的人车民用样本上先核处理域、坐标与雷达原点。为体素保存输入 original_index 集合；按地面、预筛、未成簇、形状无效、同格冲突分别记原因，缺证据保留未知。比较开/关角格预筛时增加的已标人车误抑制和粉尘召回，并统计混合栅格数量、输入丢帧率与 P50/P95 耗时。只有通过同源点对照才考虑接入。无需先改学习网络。
