# 严格粉尘任务的标签语义

派生存储：0 忽略、1 非尘、2 尘；监督损失只对 mask=true 的行，将 1/2 映为两个 logits 的 0/1。原标签始终保留。几何无效、语义不可用是两个不同条件。

| 来源 | 映射与排除 |
|---|---|
| UCHILE | 发布者原0→任务2，原1→任务1；只用原点分区，diff/flow/lidror 等不作真值。不能令原0成为 ignore。 |
| DustX 精细六传感器 | 原9→2；0、25 忽略；10 Noise、11 Rainwater 单列忽略。其余有字典依据的实体/表面类按版本映为1，包括原28 Panel 的显式本任务映射。未知编号报出，不默认为负。17 行人及车辆细类保留；不能把所有 non-dust 等同有标人车。 |
| DustX 三组 1–4 编码 | SCHEMA_UNRESOLVED；可读原语义，不进入严格监督或选模。不用框内多数类反推数值。 |
| 本地 PLY | 来源1人、2车→1；原3仅在介质为尘时→2；已知烟雾单列。原0、原4、冲突忽略。不将 reviewed 与编辑原件重复计数；既有来源声明不同于独立复核。 |
| PCD+框 | 框（可含 obj_id）与点标签分开，未标点的 task_label 全0。缺JSON并非空JSON，两者也不证明没有目标。 |
| bag | 两段试点均无逐点语义，保持全忽略；RAW不接受POST-LIO的点索引标签，算法话题和工程师产生的栅格不是GT。 |

DustX 按有限 XYZ、去除明确的全零占位后再作几何计算；有效点强度可以为0。其他域的原点占位规则随协议声明，不凭强度删点。未解决媒体、材料来源或事件身份时保留不确定状态。机器映射见仓库 datahub 模块及本地 label_schema.yaml。
